# 📋 Job & Internship Tracker

A simple, beginner-friendly web app to track your job and internship applications — built with **Python**, **Streamlit**, and **SQLite**.

## Features

- ➕ Add applications with company, role, date applied, and status
- 📊 Dashboard with live stats (total, applied, interview, offer, rejected)
- 📋 Table view of all applications, sorted by most recent
- ⬇️ Export all applications to CSV as a backup
- 🗑️ Delete an application by ID
- 🎀 Soft pastel theme out of the box (easily customizable)
- 💾 All data stored locally in a SQLite database — no external services, no sign-up

## Tech Stack

- **Python 3**
- **Streamlit** — web UI
- **SQLite** — local database (via Python's built-in `sqlite3` module)
- **Pandas** — displaying the applications table

## Getting Started

### Prerequisites

- Python 3.8+ installed

### Installation

```bash
# Clone the repo
git clone https://github.com/your-username/job-tracker-app.git
cd job-tracker-app

# (Optional but recommended) create a virtual environment
python -m venv venv
source venv/bin/activate   # on Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
```

### Run the app

```bash
streamlit run app.py
```

The app will open in your browser at `http://localhost:8501`. A `job_applications.db` file will be created automatically in the project folder the first time you add an application — this is your local database.

## Customizing the Theme

Colors live in `.streamlit/config.toml`. Change any hex code and restart the app to see it update:

```toml
[theme]
primaryColor = "#FF6F91"          # buttons, highlights
backgroundColor = "#FFF7FA"       # main background
secondaryBackgroundColor = "#FFE3EC"  # sidebar, cards
textColor = "#4A4A4A"
```

## How It Works

- `init_db()` creates the database table on startup if it doesn't already exist.
- `add_application()`, `get_all_applications()`, `get_stats()`, and `delete_application()` handle all reads/writes to SQLite using parameterized queries.
- The Streamlit UI re-runs top to bottom on every interaction, so the dashboard and table always reflect the current database state.
